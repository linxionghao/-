# 设计说明

> 状态：初稿（v0.1.0）。标 `【待定】` 的部分尚未拍板，改动前请先更新本文。

## 1. 问题定义

制造现场有两个反复出现的痛点：

1. **追溯断链**：成品要回答"用了哪批料、经过哪台设备、哪班人、哪次检验"，数据散落在 ERP、MES、纸质单据里，对不上时间轴。
2. **归因靠经验**：不良品单上只写了缺陷现象，判断是料、机、法、环、测哪一环出的问题，依赖老师傅。

本工具把两者接起来：**先有谱系，才谈归因；每个归因结论都必须能落回具体批次、工序和时间窗口。**

## 2. 范围与非目标

| 做 | 不做 |
|---|---|
| 批次/序列号谱系的正向与反向查询 | 通用 MES（工单排产、库存、财务） |
| 规则命中与统计相关，输出疑似原因排序 | 训练端到端「AI 归因模型」 |
| 输出 8D 草稿，供人修改签字 | 自动给工人或供应商定责 |
| 结构化证据留存，可回溯每次判断依据 | 视觉缺陷检测（另立模块，见 `【待定】`） |

## 3. 数据模型（草案）

```
material_lot  物料批次
   └─ work_order   工单
        └─ operation  工序
             ├─ equipment    设备
             ├─ fixture      工装（可选）
             ├─ operator     操作者
             └─ inspection   检验记录 ──> defect   缺陷条目
成品序列号 serial 与 operation 关联，形成有向无环的谱系图。
```

关键字段：每条记录都要有 **业务时间**（发生时间）与 **录入时间**，两者必须分开存。
原因见第 5 节。

## 4. 归因的四层证据

| 层 | 输入 | 输出 | 可信度 |
|---|---|---|---|
| 1. 规则命中 | SPC 判异（Nelson / Western Electric）、参数越界 | 硬证据，确定性 | 高 |
| 2. 统计相关 | 同批次 / 同设备 / 同时段 / 同操作者的集中度 | 排序后的嫌疑人 | 中 |
| 3. 因果假设 | 差异对比 + 因果推断 | 假设，**必须标注「待验证」** | 待验证 |
| 4. 人工确认 | 工程师判断 | 记入 8D 的根因 | 最终 |

**系统只负责到第 3 层。** 任何界面上都不允许出现"根因是 X"这种断言——这是产品立场，不是技术限制。

## 5. 关键技术决策

### 5.1 业务时间优先（as_of 硬闸）

质量标准与工艺参数都是有版本、有生效日期的。追溯时必须取**缺陷发生时**的版本，而不是今天的版本。
实现上按业务时间过滤，而不是按录入时间；历史数据被补录时不会污染判断。

### 5.2 谱系双向可查

- 正向（某批原料 → 受影响的成品）：用于**围堵**，算召回范围
- 反向（某成品 → 用了哪些原料/设备/参数）：用于**溯源**

两个方向都要有，只做一个的系统在现场是跛的。

### 5.3 规则引擎与统计分离

判异规则是确定性逻辑，进 `core/`，配单元测试穷举边界。
统计排序可以改算法，但不得改变"哪些是硬证据"的定义。

## 6. 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 图数据库（Neo4j）存谱系 | 多跳查询天然 | 部署重，作业场景过重 | 暂不用，先用关系库 + 递归查询 |
| 关系库自连接 | 零额外依赖，易演示 | 深链查询要写递归 | **采用** |
| 直接上 LLM 做归因 | 演示效果炫 | 无法验证，结论不可审计 | 不采用；LLM 只可用于生成 8D 措辞 |

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 无真实产线数据 | 无法验证效果 | 模拟产线 + 注入已知根因，用「根因召回率」作指标 |
| 数据模型猜错，后期返工 | 进度风险 | 先用 3 条模拟数据打通全链路，再扩表 |
| 被判「又一个 MES 半成品」 | 评价风险 | 明确非目标，README 第一段就切割边界 |
