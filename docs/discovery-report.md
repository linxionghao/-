## 在线需求分析
现有事实显示，瓶颈不在“是否用 AI”，而在追溯链的数据完整性与责任交接：手写再录入导致批次/机台缺漏（f10、f12），返工换批号后追溯不到原刀具（f11），测量单位与公差版本混用、量具校准过期（f31、f33），且各系统权限独立、无统一业务状态视图（f30）。管理层目标（返工率7.8%→4%、定位2天→4小时，f00）尚缺分节点时间基线（f01），验收口径（两类零件、完整率99%、错误放行为零，f02）也未定零件与产线。因此建议切入点优先“追溯清单与异常定位辅助+数据口径校验”，而非根因认定或放行；后者被明确排除（f05、f52）。以下假设均待访谈与回放验证，覆盖率不代表验收通过。

  依据：manufacturing-quality-f11、manufacturing-quality-f44、manufacturing-quality-f23
  推导：已发生“一批螺纹不合格品返工后换了批号，追溯不到原刀具”的事件（f11），且此类情形被列为转人工的触发条件（f44）。交接要求包含业务编号、版本、状态、未解决事项与接手人（f23），但返工换号是否保留原编号尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：复盘该事件的实际单据，确认换批号时原业务编号是否留存；在回放中验证返工单与原批次的关联字段，人工确认点为工艺工程师核对后继续（f15）。
- REQ-4 数据口径与版本校验应先于任何推荐输出
  依据：manufacturing-quality-f31、manufacturing-quality-f33、manufacturing-quality-f32、manufacturing-quality-f34、manufacturing-quality-f30
  推导：测量单位与公差版本混用、部分量具校准过期（f31），需先校验检测量值、校准证书、工艺版本与返工单的主编号、事件时间与版本字段，有歧义记录进人工修复队列（f33）。系统侧仅能读检验数据与工艺版本、不能自动放行（f32），且状态每天两次更新、超期标待刷新（f34）。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：对试点两类零件做字段级数据质量核查，统计单位/版本冲突与校准过期条数；验证接口中断时只读快照与“暂未更新”标识（f35），人工确认点为秦芮判定哪些记录可进入推荐样本。
- REQ-5 统计口径不统一会削弱验收与客户解释的可信度
  依据：manufacturing-quality-f50、manufacturing-quality-f53、manufacturing-quality-f51
  推导：工艺按缺陷原因归类、客户按不合格批次统计、返工件重复计数（f50），需固定分母、排除规则与统计周期，不能把同一业务拆成多次成功（f53）。服务侧逐笔采集交接等待与重新联系次数，不以通知数量代替完成量（f51）。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：由叶书与唐映秋共同确认批次分母与返工件标记规则，形成一页口径说明；在试点周报中并列“批次分母”与“服务侧实际完成量”，人工确认点为质量总监签字认可口径。
- REQ-6 人工兜底与审计留痕是错误放行为零的必要条件
  依据：manufacturing-quality-f40、manufacturing-quality-f41、manufacturing-quality-f45、manufacturing-quality-f43、manufacturing-quality-f44
  推导：客户图纸受限，未经复检和签核不得放行（f40）；仅授权岗位可查看相关记录，最终决定须对应审批人确认（f41）。每次建议需保留业务编号、资料版本、事实引用、建议结果、人工改动与签核人（f45），评价记录暂留90天待复核（f43）。但真实留存期限仍须按组织规则另行确定。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：在回放中模拟一次资料缺失与一次版本冲突，检查是否按f44转人工并标注触发原因、接手人与确认时间；由傅景确认停止条件清单，人工确认点为签核人留痕完整性抽查。
