# 0007. 过程能力用组内 σ 还是整体 σ：两个都算，但必须标清楚是哪一个

- 状态：已采纳
- 日期：2026-11-06
- 影响范围：`core/analytics/capability.py`、`core/analytics/spc.py`、`core/services/analytics.py`、`core/services/msa.py`

## 背景

Cp / Cpk 的分母是 σ。σ 有两种算法，结果差很多：

| 口径 | 算法 | 反映什么 | 对应指标 |
|---|---|---|---|
| 组内（within） | `σ̂ = R̄ / d₂`（或 `s̄ / c₄`） | 只含**普通原因**变差 | Cp / Cpk |
| 整体（overall） | 全部数据的样本标准差 `s` | 含普通原因 + 特殊原因 | Pp / Ppk |

同一批数据，Cpk 与 Ppk 的差可能到 0.5 以上。Cpk 高、Ppk 低，
说明过程有特殊原因在捣乱——这是有用信息，不是矛盾。

问题在于**这套系统里 σ 会被算三次**（控制图、能力分析、MSA），
三处口径不一致时，看板上会出现"Cpk=1.4 但控制图报警"这种自相矛盾的画面。
更糟的是错误不会报错：数字看着完全合理，只是偏大或偏小。

实际踩到的 bug：`sigma_within = rbar / (d2 * sqrt(n))`。
多除了一个 √n。在 n=5 时 Cpk 被**高估 2.24 倍**——一个真实 Cpk=0.6
的不合格过程会算出 1.34，判为"过程能力充足"。这个 bug 之所以危险，
是因为它给出的数字仍然在合理区间里，没有任何异常信号。

## 决策

**两个 σ 都算、都报，名字分开，绝不含糊。**

```python
sigma_within  = r_bar / d2                # 组内：Cp / Cpk 的分母
sigma_xbar    = sigma_within / sqrt(n)     # 子组均值的标准误（X̄ 图的限用它）
sigma_overall = stdev(values, ddof=1)      # 整体：Pp / Ppk 的分母
```

三条约束：

1. **`sqrt(n)` 只出现在 `sigma_xbar` 上**。`sigma_within` 是单件读数的
   标准差，它不需要再除 √n。写成 `rbar/(d2*sqrt(n))` 就是把
   "单件标准差"和"均值标准差"混成一个东西；
2. **返回值里 `cp/cpk` 与 `pp/ppk` 永远成对出现**，不提供"只算一个"的选项。
   只给一个时，用户没法看出过程是否有特殊原因；
3. **控制图的 UCL/LCL 用 `sigma_xbar`**，能力指数用 `sigma_within`。
   这两个值不同，混用会让"图上刚好在界限内"和"Cpk 达标"对不上。

`TestSigmaCaliber`（3 条回归）守这条：给定 `R̄=0.043, n=5`，
断言 `sigma_within == 0.043/2.326`，而不是 `0.043/(2.326*√5)`。

## 后果

- 好处：Cpk 与 Ppk 的差本身成为一个诊断信号（差 > 0.3 提示特殊原因）；
  三处计算共用同一组函数，口径不可能再漂移。
- 代价：返回值字段变多（`cp/cpk/pp/ppk/ca/cr/ppm`），前端要排版；
  用户需要知道 Cpk 与 Ppk 的区别——所以页面上直接写了这两个指标的口径说明，
  而不是指望用户去翻手册。
- 未来若要改：只改 `capability.py` 的三个私有函数，
  接口契约（字段名）不用动。

## 替代方案

| 方案 | 为什么不选 |
|---|---|
| 只报 Cpk（组内） | 看不出特殊原因；以为在看过程能力，其实看的是"过程在受控时的潜力" |
| 只报 Ppk（整体） | 客户验收常用 Cpk，报 Ppk 会被要求换算 |
| 取两者平均 | 最糟的选择：两个都有意义的指标，平均后两个都没有意义 |
| 让用户传一个 `sigma_caliber` 参数 | 把口径判断推给用户，而用户往往不知道该传什么；默认值一旦选错，全站数字都错 |

## 补充：P 图的控制限为什么逐点不同

P 图（不合格品率）的分母 `n_i` 每天不同，所以：

```
UCL_i = p̄ + 3·√(p̄(1-p̄)/n_i)
```

用固定控制限（取 n 的平均值）会把"产量少的那天"误判成异常——
产量 100 件时 3σ 带宽是产量 10000 件时的 10 倍。这是手画 P 图最常见的错误，
代码里用 `p_chart()` 逐点计算，不做简化。
