# 星衡精密 · 质量追溯与缺陷归因 AI 辅助项目 设计方案

版本 V1.0 ｜ 日期 2026-10-23 ｜ 密级：项目内部

> 本文档汇总项目全部前期成果编制而成：《业务需求发现报告》（36 条事实 / 六岗位，f00–f55）、《制造业质量追溯与缺陷归因 · 同行方案调研报告》、《业务流程对比图》（现有 vs 数字化）、《项目报价单》。所有需求均为待验证假设，最终以历史回放与并行试点验收为准。

---

## 一、项目概述

### 1.1 项目背景

星衡精密在"质量追溯与缺陷归因"上投入大量人力：检测表手写后再录入，批次与机台信息经常缺漏（f10）；每月 320 批、每批约 25 分钟重复录入（f12）；已发生"一批螺纹不合格品返工后换了批号，追溯不到原刀具"的真实事件（f11）。管理层希望用 AI 改善，但优先环节、验收标准与权限边界尚未确定。

### 1.2 业务目标

| 目标 | 现状 | 目标值 | 依据 |
|---|---|---|---|
| 缺陷定位时长 | 2 天 | 4 小时 | f00 |
| 返工率 | 7.8% | 4%（经营目标） | f00 |
| 批次追溯完整率 | 无基线 | ≥ 99% | f02 |
| 错误放行 | — | 零 | f02 / f42 |
| 重复录入工时 | 约 133 小时/月 | 显著下降 | f12 / f51 |

### 1.3 范围边界（红线）

- **做**：异常定位辅助 + 追溯清单自动生成（f05 / f52）。
- **不做**：不自动认定根因、不自动放行；AI 输出仅为辅助，最终判定由授权岗位签核。
- **实施方式**：历史资料回放验证 → 4 周小范围并行试点，不替换现有业务（f05）。
- **预算**：首期 18 万元，含集成、培训与验证（f03）。

## 二、现状分析

### 2.1 主流程与痛点

现有主流程：首件检验 → 巡检 → 不合格隔离 → 原因分析 → 返工 → 复检（f01）。管理层尚未量出各节点等待与处理时间，"4 小时"目标暂缺分节点基线（f01）。

| 痛点 | 事实依据 | 影响 |
|---|---|---|
| 手写再录入，批次/机台缺漏 | f10 | 直接威胁 99% 完整率 |
| 重复录入 25 分钟/批 × 320 批/月 | f12 / f51 | 约 133 小时/月整块时间 |
| 返工换批号丢原编号（螺纹批事件） | f11 | 追溯断链，列为停止条件 f44 |
| 单位与公差版本混用、量具校准过期 | f31 | 脏数据直接进归因则结论失真 |
| 关键说明留在便签/群里，不随单据交接 | f14 | 换班换批号时信息断点 |
| 三系统权限独立、无统一业务状态视图 | f30 | 跨系统拼数口径不一 |
| 统计口径不统一（工艺按原因 / 客户按批次） | f50 / f53 | 客户解释与验收可信度受损 |

### 2.2 数据与接口条件

- 现有系统：QMS、MES、量具采集软件，三套账号权限独立维护（f30）。
- 接口边界：**只读**检验数据与工艺版本，**不能**自动放行产品（f32）。
- 更新节奏：每天两次更新已授权业务状态，超一个更新周期标"待刷新"（f34）。
- 接口中断：使用带时间戳的上一份只读快照并显示"暂未更新"，重连后按业务编号去重补齐（f35）。

## 三、同行方案调研结论（设计依据）

调研覆盖 GitHub / Gitee / arXiv / IEEE / ScienceDirect，时间窗 2024–2026。总体判断：**追溯侧成熟、归因侧空白**。

| 来源 | 许可 | 本项目吸收点 |
|---|---|---|
| crbnos/carbon（2.7k★） | 自定义，只读设计 | 谱系数据模型：质量记录与工单、工艺路线同源 |
| HipiCloud/hipi-trace | GPL-3.0 | 码段与节点建模思路（不复制代码） |
| liuweichaox/Ingot | Apache-2.0 | **归因三段式工作流**；证据作为一等对象存储 |
| causalgraph/causRCA | Apache-2.0 | "什么算归因正确"的评测口径 |
| statistical-process-control | 未声明 | Nelson / Western Electric 判异规则入核心层 |

关键结论：

1. **不做通用 MES**——carbon 已做到极致，再做只会单薄。
2. **不训练"归因模型"**——工业界认可的归因是流程：硬证据 → 统计线索 → 因果假设 → 人签字确认。算法只在"统计线索"层发力。
3. **代码全部自写**，只借鉴数据模型与流程设计，规避许可证风险。
4. 行业对标：商业 QMS（SAP QM / Siemens Opcenter）把归因放在 CAPA/8D 模块，卖的是流程规范；合规驱动为 IATF 16949 第 8.5.2.1 条标识与可追溯性强制条款。

## 四、总体设计

### 4.1 设计原则（四条结构性设计）

1. **谱系数据模型**：物料批次 → 工单 → 工序 → 设备/工装/操作者 → 检验记录 → 成品序列号；同时支持正向（围堵）与反向（溯源）查询。
2. **归因分层、每层证据冻结**：规则命中（SPC 判异/参数越界，硬证据）→ 统计集中度（同批次/同设备/同时段，软证据）→ 因果假设（标注"待验证"）→ 人工确认（记入 8D 根因）。系统只输出到"假设"。
3. **"当时的规范"是硬闸**：质量标准与工艺参数限值按业务时间（as_of）取缺陷发生时的版本，不按录入时间。
4. **SPC 判异规则进核心层**：确定性逻辑、可穷举测试，同时作为归因的"缺陷前兆"触发器。

### 4.2 系统架构（五层）

| 层 | 组成 | 说明 |
|---|---|---|
| 数据源层 | QMS / MES / 量具采集软件（只读） | 带时间戳快照，每日两次刷新 |
| 接入校验层 | 口径与版本校验模块 | 主编号 / 事件时间 / 版本字段对齐；单位、校准、as_of 版本；歧义记录拦截进人工修复队列（f33） |
| 智能体层 | Agent-1 / 2 / 3 | 读同一数据、用同一模型档位的执行步骤合并为一个智能体 |
| 审查闸门层 | 四道不可逆前审查员 | 根因入库、返工换号、复检放行、回写答复，全部具名签核 |
| 应用与留痕层 | 追溯清单 / 证据包 / 8D 草稿 / 审计日志 | 六要素留痕横切全程（Agent-4） |

### 4.3 智能体设计

合并判据只有两条：**读同一份数据 + 用同一档模型**。

| 智能体 | 职责 | 数据源 | 模型档位 | 输出 |
|---|---|---|---|---|
| Agent-1 数据接入与口径校验 | 三系统只读快照、字段口径与版本校验 | QMS/MES/量具快照 + 工艺版本库 + 检测模板 | L0 确定性规则 + L1 结构化抽取 | 可用样本集、待刷新标记、歧义清单、as_of 版本锁定 |
| Agent-2 谱系追溯与围堵 | 正反向追溯、返工换号回连 | 批次谱系 / 工单 / 工序 / 设备工装 / 返工单 | L2 关联检索与排序 | 追溯链、围堵范围清单、原编号回连 |
| Agent-3 证据聚合与归因假设 | 证据聚合、线索排序、8D D2–D5 草稿 | 检验记录 / 工艺参数 / 设备状态 / 历史 8D | L2–L3，**止于"待验证"假设** | 证据包、疑似原因排序、8D 草稿 |
| Agent-4 留痕与交接（横切） | 全程六要素留痕 | 签核记录 / 版本变更 / 交接单 | L0 模板化写入，不推理 | 审计日志、交接单 |

### 4.4 流程设计

两张流程图详见附件《质量追溯-业务流程对比图.html》：

- **图一 · 现有业务流程（纯人工）**：10 步主链 + 3 个横向回退分支 + 右侧"人工模式痛点"栏。
- **图二 · 数字化业务流程（AI 辅助）**：Agent 主链 + 3 个决策菱形 + 4 道红色审查员菱形闸门 + 右侧"人工兜底回路"。

关键决策点：数据是否完整且口径一致、追溯链是否闭合（兼停止条件 f44 检查）、证据是否支撑假设。停止条件（换批号追不到原刀具、资料缺依据、两版本冲突、关键系统不可用）在进入归因前即硬停，直连 L4 傅景。

### 4.5 数据模型要点

- **谱系六节点**：首件检验 → 巡检 → 不合格隔离 → 原因分析 → 返工 → 复检，每节点挂业务编号 + 版本 + 时间戳。
- **返工换号回连**：返工单强制携带原业务编号，新批号与原刀具链双向关联（f11 / f23）。
- **证据一等对象**：证据包独立存储，引用具体记录与版本，支持审计重建（借鉴 Ingot）。
- **六要素留痕**：业务编号、资料版本、事实引用、建议结果、人工改动、签核人（f45）。

## 五、关键机制设计

### 5.1 人工兜底回路与四级升级

| 级别 | 接收人 | 触发 |
|---|---|---|
| L1 现场复核 | 林亦舟（生产班组长） | 常规存疑、低置信 |
| L2 跨岗分派 | 唐映秋（质检班长 / 工艺） | 歧义记录、证据不足、退回重取 |
| L3 时限升级 | 顾明岚（质量总监 / 生产经理） | L2 超时未闭环 |
| L4 红线否决 | 傅景（产品安全负责人） | 停止条件（f44）、可否决上线（f04） |

横向专项：数据侧秦芮（修复队列 / 只读快照 / 回写确认）、客户侧叶书（争议受理，未经确认不承诺结果 f54）。转人工必须标注**触发原因、接手人、确认时间**（f44），不能只给模糊提醒。

### 5.2 降级与中断处理

接口中断或快照超期：降级为带时间戳只读快照 + "暂未更新"标识，现有人工流程继续运行；待刷新与歧义记录**不进自动推荐样本**（f33 / f34 / f35）。

### 5.3 权限与合规

- 客户图纸受限，未经复检和签核不得放行（f40）；AI 不替代签核动作。
- 仅授权岗位可查看检测量值、校准证书、工艺版本与返工单；最终决定、对外承诺、资产变更须对应审批人确认，不借用他人账号（f41）。
- 不记录账号口令或不必要个人信息（f45）。
- 试点原始资料按授权范围保存，评价记录暂留 90 天，期满由傅景复核删除或归档（f43）；真实期限按组织规则另行确定。

## 六、评测设计

1. **Golden Set**：选取试点两类零件历史批次，覆盖"首件→巡检→隔离→分析→返工→复检"全链路回放；借鉴 causRCA 口径定义"什么算归因正确"。
2. **注入根因可召回率**：参考 manufacturing-traceability 的"模拟产线 + 注入已知根因"做法，核心指标为注入根因能否被找回。
3. **回放验收线**：回放通过率 ≥ 95%、追溯完整率 ≥ 99%、错误放行为零。
4. **每周反馈闭环**：质检 / 工艺 / 客户质量经理三侧误判例子与未解决问题每周合并，质量总监确认改进负责人，先复测验收口径再更新规则版本（f55）。
5. **统计口径**：固定批次分母、排除规则与统计周期，返工件单独标记不重复计数；"批次分母"与"服务侧实际完成量"并列周报（f50 / f53）。

## 七、实施计划（12 周）

| 阶段 | 周次 | 内容 | 出口 |
|---|---|---|---|
| 一、诊断与基线 | W1–W2 | 六岗位访谈复盘、字段级数据质量核查、缺漏率基线、确定两类零件与试点产线 | 基线报告 + 试点范围签字 |
| 二、设计 | W3–W4 | 架构与数据模型设计、接口盘点、Golden Set 设计、安全与权限架构、验收标准定义 | 设计评审通过（傅景/叶书会签） |
| 三、数据资产建设 | W4–W6 | 历史数据清洗、结构化、标注、权限梳理、检索切分 | 可用样本集 |
| 四、系统构建 | W5–W9 | Agent-1/2/3/4 开发、三系统只读对接、口径校验模块、私有化部署 | 测试环境可用 |
| 五、回放验证 | W9–W10 | Golden Set 历史回放、幻觉与越权注入测试、审计留痕验证 | 回放通过率 ≥ 95% |
| 六、并行试点 | W10–W12 | 4 周小范围并行（与人工并行，不替换）、每周反馈闭环、现场培训与应急演练 | 试点验收（错误放行为零） |

## 八、验收标准总表

- 两类零件试点、批次追溯完整率 **≥ 99%**、错误放行为**零**（f02 / f42）；
- 缺陷定位从 **2 天缩短至 4 小时**（f00）；
- 返工环节强制保留原业务编号，换批号不丢追溯链（f11 / f23）；
- 歧义 / 待刷新记录 100% 拦截，不进自动推荐样本（f33）；
- 人工兜底与审计留痕全覆盖，任一不可逆动作前有具名签核（f40 / f45）；
- 触及停止条件即转人工并标注触发原因、接手人、确认时间（f44）。

## 九、风险与待验证事项

| 风险 / 待验证 | 说明 | 应对 |
|---|---|---|
| 试点范围未定 | 两类零件、产线、回放时间段未定，验收无法落地 | 阶段一出口前由顾明岚召集傅景、唐映秋签字 |
| 缺漏率无基线 | 99% 完整率缺对照 | 先抽样统计近月缺漏率 |
| 分节点时间基线缺失 | 4 小时目标可达性不可判 | 试点先量各节点等待/处理时间（f01） |
| 数据不干净污染结论 | 单位混用、校准过期 | 口径校验先于一切推荐输出 |
| 返工换号原编号留存未核实 | 需复盘螺纹批事件原始单据 | 列为回放必测场景（f15） |
| 统计口径争议 | 工艺/客户口径不一致 | 叶书 + 唐映秋共定一页口径说明，质量总监签字 |
| 留存期限未定 | 90 天为暂定 | 按组织规则另行确定（f43） |
| 幻觉与越权风险 | AI 输出被当作放行依据 | 幻觉/注入测试 + 审查闸门 + 六要素留痕 |
