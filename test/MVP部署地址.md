## 四、启动与停止

### 4.1 一键启动

```bash
# 仓库根目录执行
bash scripts/run_server.sh 8000
```

脚本会先建索引（幂等，语料未变时几秒完成），再启动服务。Windows 下等价命令：

```powershell
$env:PYTHONPATH="src"
D:\python\python.exe -m uvicorn quality_trace.api.app:app --host 0.0.0.0 --port 8000
```

### 4.2 停止

```bash
# 前台运行时按 Ctrl+C
# 后台运行时按端口找进程
netstat -ano | findstr :8000
taskkill /PID <PID> /F
```

### 4.3 监听地址说明

- `--host 127.0.0.1`：仅本机可访问，最安全，适合单人演示；
- `--host 0.0.0.0`：局域网可访问，适合现场多终端演示，但**须确保所在网络可信**；
- 不建议在未配置 HTTPS 与反向代理的情况下直接暴露到公网。

## 五、部署到公网的三种路径

> **2026-11-06 更新**：本项目已实际采用「托管沙盒」方式上线（WorkBuddy 应用发布），公网地址见第一节。
> 以下三种路径作为后续长期部署的备选方案保留。

MVP 当前是本机部署。若评审要求公网可访问，按成本从低到高有三种选择：

| 方案 | 做法 | 适用 | 代价 |
| --- | --- | --- | --- |
| **内网穿透** | 用 frp / ngrok 把 8000 端口映射到临时公网域名 | 一次性演示、评审 | 免费额度够用；域名临时，重启即失效 |
| **云主机自建** | 1 核 2G 轻量云主机 + Nginx 反代 + systemd 托管 | 试用期 1–3 个月 | 约 60–100 元/月；需自签或申请证书 |
| **容器化托管** | 打镜像推镜像仓库，用云容器服务托管 | 长期运行、多实例 | 需改造配置外置与数据库迁移 |

**推荐**：课程评审用内网穿透即可，不必上云。评审结束后关掉，避免暴露演示数据。

### 5.1 内网穿透示例（frp）

```ini
# frpc.ini
[common]
server_addr = <frp 服务端地址>
server_port = 7000
token = <token>

[quality-trace]
type = http
local_port = 8000
custom_domains = <分配到的域名>
```

### 5.2 云主机部署要点

1. **不要用 SQLite 扛并发**：多实例部署必须换 PostgreSQL，且 `db.py` 里的建表语句需适配；
2. **配置外置**：`config/llm.yaml` 与密钥走环境变量，不进镜像；
3. **反向代理加超时**：问答是 SSE 流式响应，Nginx 需设 `proxy_buffering off` 与 `proxy_read_timeout 300s`，否则回答会被截断；
4. **静态资源缓存**：`src/quality_trace/web` 下的页面可加 `Cache-Control`，但 `chat.html` 不建议长缓存，改版后前端会取到旧版。

## 六、上线前必做的五件事

1. **改掉演示口令**：三个账号密码目前等于账号名；
2. **换掉 JWT 密钥**：默认密钥在代码中，必须用环境变量覆盖；
3. **关掉 `/docs`**：接口文档对公网暴露会泄露全部端点结构；
4. **配置 LLM 密钥**：不配也能跑，但只走关键词检索，回答质量与带模型时有明显差距；
5. **确认知识库来源授权**：当前语料为自建演示文档，接入企业标准前须确认可公开范围。

## 七、当前部署的真实限制

如实说明，避免评审时被追问：

| 限制 | 具体表现 | 影响 |
| --- | --- | --- |
| 未配置大模型密钥 | 健康检查 `llm_key_ready=false`，问答走 `bm25_only` 降级 | 回答是检索材料拼装，不是生成式回答 |
| 单进程 + SQLite | 并发写入会排队，WAL 只缓解读阻塞 | 超过 20 人同时提交建单会明显变慢 |
| 沙盒为临时环境 | WorkBuddy 托管沙盒，重启后数据以仓库内演示数据为准 | 线上产生的业务数据不持久，不作生产使用 |
| 未接设备与工艺数据 | 谱系只到物料批与工单 | 归因无法自动排到机台／刀具级 |
| 无备份策略 | 数据在 `data/trace.db` 单文件 | 误删即丢，长期部署须配定时备份 |
